The Builder's Toolkit

A plain-language reference, matched to your comfort level — a companion to the Bridge edition, for the December 2026 Siloam AI Hackathon.

Match the tool to the builder

This is a reference, not a reading assignment — skim it, find the row that sounds like you, and pick one thing to try. You do not need to be an engineer to build something useful. The single most important idea here is: start where you are. A non-technical analyst and a software engineer will reach for different tools, and both are right. The tools below are grouped from the most approachable (no coding at all) to the most technical (for people who write software), with quick-start stacks and a hospital data-safety box at the end. When in doubt, start at the top of the list and only climb as far as your project actually needs.

Quick-start stacks

Not sure how to begin? Pick the goal that matches and start there.

Fastest no-code prototype: open Claude Cowork or Claude Artifacts, describe the tool you want, and iterate. You'll have something demoable in an afternoon.

Fastest RAG prototype (answers from our own documents): upload your policies or contracts to NotebookLM (or use RAG inside Claude Cowork) and ask questions grounded in them, with citations.

Fastest agent prototype (a multi-step workflow): start in Claude Cowork with a clear goal and your files; layer in a no-code automation (Zapier/Make) or an API only if the workflow truly needs to reach other systems.

Not sure where to start at all? Start with Claude Cowork if you don't code, or Claude Code if you do. Both let you go from idea to working prototype quickly, and both keep you in control of every step.

Before you build: hospital data-safety essentials

We are a hospital, so this box matters more than any tool on the list. Please read it, and treat it as non-negotiable for anything you build — at the hackathon or after.

Data safety

One line to remember: build boldly on fake data, and treat real data with the same care we always have.

The safeguards we spent the whole series learning — human-in-the-loop, least access, clear approval — apply from your very first prototype.

A closing word

You do not need to master this list. You need to pick one tool that fits where you are, and try one small idea. That's the whole point of the hackathon, and this reference exists only to remove the "but which tool?" hesitation. Start at the top, stay small, keep a human in the loop, protect our patients' data — and build something. We can't wait to see what you make in December.
